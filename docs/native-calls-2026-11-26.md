# Native call validation — 2026-11-26

The native daemon's basic single-line call flow now works with the KN-3110
and the lab FreePBX: dial tone, digit collection, outbound calling, inbound
ring/answer, intelligible speech both ways, hangup from either side, and
successive calls without a device reset. This is operator-confirmed hardware
validation, not just a simulated SIP exchange.

The PBX extensions were 2005 (adapter) and 69 (test phone). Credentials were
read through a hidden prompt and were not saved. Original captures containing
audio and SIP authentication exchanges remain local under
`captures/2026-11-26/`; only derived structural/timing reports are committed.

## Experiments and corrections

### 1. Baseline incoming call

The prior committed daemon received INVITE, rang, received OFFHOOK, sent its
answer sequence and completed SIP ACK. It sent 1,334 voice frames to USB but
received no handset audio. The user did not retain a listening result, so no
subjective audio claim is made for this run. The far end ended the call; a
later ONHOOK repeated the entire audio shutdown sequence and the dongle
returned to bootloader mode.

Evidence: `native-inbound-1/session-{usb,network}.pcap` and `session.log`.

### 2. One-command audio-enable experiment

Reinspection of the original working oracle pcap found an omitted command:
`270300` at 7.436338 s, after the answer operations and immediately before
the first handset-to-host voice frame at 7.444051 s. The previous audit had
incorrectly treated its five answer operations as the complete media setup.

An otherwise unchanged daemon was tested with the harness sending `270300`
about 200 ms after incoming answer. It received 793 USB voice frames, and the
operator confirmed intelligible speech in both directions. Local ONHOOK
ended the call via BYE, and the dongle stayed in service mode. `270300` is
now scheduled by the daemon when media starts. Broader semantics of the
command's bit mask remain unproven; this result establishes the observed
handset-audio enable behavior.

The operator reported regular clicking. Measured rates exposed a second bug:

| Path | Before pacing fix | After pacing fix |
| --- | ---: | ---: |
| PBX → adapter RTP | 49.94 packets/s | 50.01 packets/s |
| adapter → USB | 44.17 frames/s | about 50 frames/s |
| adapter → PBX RTP | 46.60 packets/s | 50.00 packets/s |

Both media loops previously set the next deadline to `now + 20 ms`, which
accumulated processing/receive overhead. They now advance the existing
deadline and bound reads by the next tick. Missed ticks are skipped rather
than sent in a burst. Clock-driven tests reproduced 46 frames/s before the
fix and pass at approximately 50 afterward.

Evidence: `native-inbound-candidate/`; derived report:
[native-call-candidate-2026-11-26.json](native-call-candidate-2026-11-26.json).

### 3. Corrected daemon, incoming and outgoing in one session

Incoming: extension 69 called 2005, the analog phone rang and was answered,
and speech worked both ways. The operator confirmed the regular clicking
was gone. The calling phone ended the call, followed by analog ONHOOK. The
daemon stopped media once, acknowledged BYE, and handled later ONHOOK with
tone stop rather than repeating audio shutdown. Heartbeats remained healthy.

Outgoing: analog OFFHOOK, digits `6`, `9`, `#`, authenticated INVITE, 100/180,
200, ACK, two-way speech, analog ONHOOK and BYE/200 all completed. The user
confirmed dialing, speech and hangup. Both calls ran without rebooting or
restarting the daemon between them. The adapter stayed at PID 0001 afterward.

Evidence: `native-paced-calls/`; derived report:
[native-calls-paced-2026-11-26.json](native-calls-paced-2026-11-26.json).
The deployed code hashes match
[native-call-source-2026-11-26.sha256](../artifacts/experiments/native-call-source-2026-11-26.sha256).

### 4. Dial tone, separately verified

With no keys pressed, the user confirmed a steady dial tone on lifting the
analog handset. OFFHOOK at 00:16:52 and ONHOOK at 00:16:55 were captured.
No call was placed. The distinction matters: DTMF heard during dialing may
be generated by the handset and does not by itself validate dial tone.

Evidence: `native-tone/`. The bounded session exited, removed its SIP Contact,
and left the dongle in service mode. No daemon remains running from the tests.

## Remaining audio-quality issue

The operator heard a brief noise on extension 69 when hanging up the analog
phone. The outgoing call's 378 USB input frames and 378 transmitted RTP
payloads match byte-for-byte and in order. The final USB frame contains a
sharp spike: decoded PCMU RMS about 5,842 and peak 32,124, compared with RMS
around 15 for several preceding quiet frames. The last RTP packet precedes
ONHOOK/BYE by about 840 ms. This rules out RTP continuing after BYE in this
run; a transient is already present in the final handset-to-host audio.

The precise line/firmware cause and any safe suppression are still open.
No speculative clipping filter or added voice delay was introduced.

## Capture methodology corrections

- A canceled/timed-out USB read may contain partial data. PyUSB 1.3.1's
  libusb backend explicitly returns transferred bytes on a timeout. One
  64-byte partial completion in the candidate capture must be retained to
  reconstruct subsequent frames. Excluding nonzero-status IN data produced
  a false offline count of 733 rather than the actual 793 frames. The daemon
  handled the partial data correctly; the audit tool is now corrected, reports
  completion statuses and has a regression test for the split frame.
- `tcpdump -i any` on the bridge host records mirrored copies of RTP packets.
  `tools/audit_media.py` deduplicates identical flow/SSRC/packet data before
  measuring rates. A synthetic regression verifies that mirrors do not double
  the apparent rate. No audio contents are printed by the audit tool.
- A capture containing two calls has long idle gaps. USB timing reports now
  give continuous runs separated by more than 200 ms; the whole-file span is
  not reported as a single media rate. Such runs are not automatically calls.
- The live-session harness exits nonzero on a fatal transport stop, preserves
  existing captures, and keeps normal shutdown separate from the USB stop
  event so deregistration can finish. It avoids idle duplicate audio shutdown.

## Scope

These tests establish the basic native single-line ATA flow with this dongle
and PBX. Second-jack operation, long-duration soak, USB reconnect recovery,
all network-failure cases and broader PBX compatibility remain unverified.

## Live regression at d0c2e2a (later session)

The operator reconnected the dongle and tested the reviewed build from a separate
temporary deployment, without installing or enabling a service. Real Linux
sysfs discovery selected the bootloader tty; cold boot reached service identity
`31b7:0001`, the 296-operation initialization completed and SIP registration
succeeded with a 299-second lease.

Operator-confirmed results:

- Inbound: ringing, clear two-way speech, analog hangup disconnects the PBX phone.
- Outbound: dial tone/dialing and two-way speech work. Hanging up the PBX phone
  leaves the analog handset silent; the daemon logged remote BYE before the
  operator replaced the handset. This is successful call teardown, without an
  implemented disconnect/busy tone.
- The brief closing thump is still audible at the MacBook endpoint. A separate
  outgoing reproduction included three quiet seconds before analog hangup;
  the operator heard the thump again. Its USB/network capture is retained
  locally under `captures/2026-11-26/thump-d0c2e2a/`. All 352 handset-to-host
  USB payloads match transmitted RTP byte-for-byte, with no sequence gaps.
  The final USB frame has decoded PCMU RMS about 9,195 and peak 32,124,
  compared with RMS 21–100 in the preceding quiet frames. That frame
  precedes ONHOOK by about 840 ms; the last RTP precedes BYE by 822 ms.
  There are no outgoing RTP packets after BYE. The repeated signature places
  the spike upstream of RTP; it does not distinguish handset mechanics, line
  circuitry or firmware. A stationary-receiver/manual-cradle-switch control
  remains unperformed because the operator left and disconnected the dongle.

These results validate the exercised single-line calls on this build. They do
not validate service installation, automatic recovery, shutdown Contact removal,
a second port or long-duration operation. Linux unit verification reached an
installation prerequisite failure (the example's `/opt/lineata/.venv/bin/python`
was absent); no service was installed.

The subsequent operator disconnect also exercised real device loss: the daemon
logged USB errno 19 at 12:08:44 and a confirmed Contact-specific `expires=0`
response at 12:08:45, then exited. Inspection found no remaining test daemon or
capture processes. This demonstrates device-loss cleanup and PBX acknowledgment
of removal in this session; automatic service restart remains untested.

## Away-from-home checks with the dongle absent

A silent probe used the unchanged d0c2e2a registrar, SIP listener and shutdown
implementation against the real PBX; only hardware and dialing entry points
were excluded. It authenticated a REGISTER (299-second grant), then called
request_shutdown() and shutdown(timeout=10). The PBX challenged both
transactions; the authenticated removal returned 200 with the probe's Contact
absent from that response. Both SIP threads stopped and the socket closed;
there were no call objects, USB handles or attempted USB/dial operations. The
bounded test exited 0. This observes the reply's contact list, rather than an
independent query of PBX registrar state.

The preceding hardware session log also records four successful renewals at
239-second intervals, before each 299-second grant expired. This is real-PBX
renewal evidence for this configuration, not broader PBX compatibility.

Linux systemd/udev 257.13 checks: udevadm verify deploy/99-lineata.rules
returned 0. systemd-analyze verify --man=no deploy/lineata.service returned 1
for the absent installation prerequisite /opt/lineata/.venv/bin/python.
A temporary copy with only that ExecStart interpreter replaced by the existing
/usr/bin/python3 returned 0, establishing parser-level evidence only. The
original unit and rules were unchanged; no packages, service or udev rules
were installed, enabled, reloaded or triggered. Service operation, stop timing
and automatic restart still require separate validation.

The reusable check is now tools/sip_lifecycle_probe.py. From the checkout on the
test host, run:

    timeout -k 3 -s INT 30 python3 tools/sip_lifecycle_probe.py \
      --pbx <PBX> --login <EXTENSION> --local-ip <HOST_IPV4>

It prompts privately for the SIP secret and uses an ephemeral local SIP port.
An incoming call receives 480; no USB session or call can be originated. The
promoted lifecycle was live-tested successfully; the subsequent lease-reporting
snapshot correction was covered offline. Its fallback
cleanup refuses to mutate registration state while the registrar remains
alive, and always closes the listener socket on a cleanup exception. Offline
fault-injection tests cover these guards. Reported lease duration is captured
before shutdown resets the per-transaction registration state.

## Bounded registration-loss recovery check

With no dongle or calls, a subclass of the silent lifecycle probe discarded
only its own outgoing REGISTER datagrams for six monotonic seconds. The
registrar retry/backoff implementation was unchanged; no firewall rules or
PBX services were modified. Four sends were discarded between 0.001 and 3.502 seconds. The gate opened
at 6.001 seconds; real-PBX registration succeeded at 14.006 seconds, about
8.005 seconds later, with a 299-second grant. Real shutdown confirmed
Contact removal; both SIP threads and the socket closed, no call/USB/dial
attempt occurred, and the probe exited 0 after 14.551 seconds.

This is evidence for recovery from locally injected outbound packet loss.
It does not prove recovery from an actual server restart, network route loss
or expiration of an established registration during a prolonged outage.
